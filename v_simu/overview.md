# 概要
- unity で生成する経営シミュレーションゲームにおいて、ゲーム内でAI（AWS Bedrockで実装）を呼び出して一部テキストやセリフをプレイヤーごとにカスタマイズした形で書き換える

# アーキテクト
## フロントエンド
- unity

## バックエンド
- AWS
- 利用サービスは以下
    - API Gateway
    - Lambda
    - Bedrock
    - DynamoDB

### AIシステム
- モデルは AWS Bedrock から呼び出す
- 初期段階では Nova lite を利用する
- APIエンドポイントは API Gateway で作成し、 Lambda を経由して Bedrock のモデルを呼び出す
- AIシステムの障害時にはデフォルトのテキストを利用する

### 記憶モデル
- DynamoDB を利用し、キャラクターの記憶モデルを構築する
- テーブル種別は下に記載
    1. conversation logs
        - 会話ログを保存する
        - 直近 10 ~ 20 程度の会話を参照する
    2. character memorys
        - 重要記憶を保存する
        - キャラクターにとって重要なイベントについて抽象化した記憶を保存する
        - 最近の出来事ほど強く、時系列が遠くなるほど影響度を弱めていく
        - 影響度が閾値を超えたら、それ以上のイベントは参照しない
        - これにより、「キャラクターにとって重要」または「最近の出来事」が強い影響力を持つ

### プロンプト
- 基本的なプロンプト構成は以下

#### システムプロンプトの構成

`createSystemPrompt` 関数で組み立てられ、Bedrock Converse API の `system` フィールドに渡される。

| セクション | 内容 |
|---|---|
| キャラクター定義 | 名前・性格・話し方・プレイヤーとの関係性（`characterProfile` から注入） |
| 現在の感情状態（mood） | 喜び・不安・怒り・疲労・自信・孤独感。各値は 1〜100 のスコアで管理し、テキストラベル付きで注入 |
| プレイヤーへの感情（perception） | 信頼・好感・尊敬・恐れ・依存・親しみ。同上 |
| 重要な記憶 | `character_memorys` テーブルから取得した抽象化済み記憶を箇条書きで注入 |
| 最近の会話 | `conversation_logs` テーブルから取得した直近 10 件を時系列順で注入（JST 日時付き） |
| 制約事項 | キャラクター維持・日本語のみ・セリフ120文字以内・AI開示禁止 など |
| 出力フォーマット | セリフ本文と `<state_update>` ブロックの2パートを必ず出力させる |
| 思考手順 | シチュエーション推定 → 返答生成 → キャラクター整合チェック → 感情差分算出の4ステップ |

#### state_update の仕組み

モデルはセリフの末尾に以下形式の JSON ブロックを付与して出力する。

```
（セリフ本文）
<state_update>{"mood":{"joy":差分,...},"perception":{"trust":差分,...}}</state_update>
```

- `parseReply` 関数が正規表現で `<state_update>` を抽出し、セリフ本文と分離する
- 差分（整数）を現在値に加算し、1〜100 にクランプして `CHARACTER_MEMORY_TABLE` へ保存する
- 1 回の会話あたりの変化量の目安は ±1〜5（プロンプトで指示）

#### 感情・関係値の初期値

初回アクセス時（DynamoDB に状態未保存）はコード内のデフォルト値を使用する。

| カテゴリ | パラメータ | 初期値 |
|---|---|---|
| mood（自己感情） | 喜び / 不安 / 怒り / 疲労 / 自信 / 孤独感 | 35 / 62 / 20 / 48 / 30 / 10 |
| perception（対プレイヤー感情） | 信頼 / 好感 / 尊敬 / 恐れ / 依存 / 親しみ | 72 / 55 / 80 / 12 / 30 / 65 |
